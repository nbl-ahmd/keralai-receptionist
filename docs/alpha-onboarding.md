# Invited tester onboarding

1. Open the private email-bound invitation link. Invalid, expired, consumed and revoked links disable registration. Invitations are bearer secrets; do not post links publicly. Registration pages set a no-referrer policy; hosting/proxy logs must also redact query tokens.
2. Register with the bound email, name and password. Signup cannot accept a client-selected plan, workspace ID, wallet amount or admin role.
3. Choose personal/business/other purpose, identity/language and assistant instructions. Knowledge is optional and capped by the plan. Save each step and resume later.
4. Test assistant in the browser. Grant microphone permission and use a consenting test phrase. No KYC or personal API key is required for this path. Observe a real reply only after the organiser configures managed Gemini. Missing operator configuration gets a clear error.
5. Open the dashboard. Home and Phone show remaining minutes/credit; Billing shows included/used/reserved usage, concurrency and session duration. Pending CDR reservations are labelled. Low/exhausted allowance directs testers to the organiser; there is no payment checkout.
6. Optional own-key mode is in Advanced → AI connection. Switching mode is explicit, owner/admin-only and audited; it preserves the stored key. Missing BYOK never borrows the platform key, and BYOK never bypasses quotas.
7. Phone setup remains a separate approved KYC/provisioning/carrier test. Invitation credit does not authorise spending or real identity verification.

The mobile acceptance paths are registration/onboarding, Home, Assistant, Phone, Billing and Calls at 360/390/414 pixels, plus the existing ten-viewports and keyboard-dismissible phone dialog checks. Fixtures avoid paid model/provider calls.
