# Alpha operator runbook

Use two environments: Next.js on Vercel and bridge on Render, each with process settings corresponding to its local env template. Choose the intended staging database first, back it up and apply 001–015. Existing encryption/signing keys must match and remain stable. Never deploy `TEST_SCHEMA` or `KERALAI_TEST_SCHEMA`. `AI_ENVIRONMENT=alpha` labels the process; per-tenant DB mode selects credentials. Use a dedicated alpha Google project/key, separate from development/production, and approve quota/budget there yourself.

Required shared settings: database, bridge signing/encryption secrets, platform Gemini key, AI environment, request/estimate limits, pricing version and independent browser/phone/purchase switches. App-only: strong Better Auth secret/canonical URL, public bridge WSS URL, operator user-ID allowlist, invitation issuance, provider parent credentials, actual public callback/bridge origins, customer paise prices and cron secret. Bridge-only: canonical browser origin, Render-injected port and protected metrics settings. Provider reserve rate must be commercially approved; blank deliberately prevents phone admission. Local files preserve existing real secrets and contain blanks for unknown values.

Set `ALPHA_INVITE_ISSUANCE_ENABLED=1` only when ready to invite. Existing operator account signs in; find its Better Auth user ID through restricted database inspection and allowlist that exact ID. Tenant roles or emails do not grant platform admin. In Admin → Alpha operations, supply a reason for every action. Create an email-bound invite, copy the returned link once, and deliver it privately yourself. Operator actions carry a unique reference; promo credit retries use the same reference. Review the Alpha plan and caps before issuing links.

Admin displays paged tenants, current plan/usage/credit/active sessions, pending CDR count, global voice gates, aggregate provider actual costs, AI request/voice estimates and oldest pending settlement age. It can revoke invites, suspend/resume tenants, disable voice/purchase, grant audited promo credit and edit phone quota. Authenticated APIs additionally support plan/subscription changes, other quota overrides and platform numeric caps; all reject unknown fields. Reason/reference audit is stored; keys/PAN/Aadhaar are never part of snapshots.

Monitor structured `alpha.invite.*`, `tenant.entitlement.denied`, `gemini.session.*`, `phone.call.denied`, `wallet.promo_credit.granted`, existing `vobiz.*`/billing/reconciliation events and private bridge latency metrics. Alert on rising denial/backlog age, near quota/cost caps, negative wallet, repeated provider timeout and missing/late CDR. Usage estimates must not be represented as actual AI spend. No external telemetry service/alerts were configured by implementation.

Before first tester:

1. Run lint, build, unit, integration, UI and `npm run test:smoke -- --strict` on intended staging configuration. The smoke performs read-only SQL and optional app/bridge health GETs; it never calls Google/Vobiz. Set `SMOKE_APP_ORIGIN`/`SMOKE_BRIDGE_ORIGIN` for deployed health checks.
2. Verify a canonical-origin invitation registration, assistant setup and real browser reply with an approved Google key. Confirm current usage reservation then closure, tenant-only transcript, and operator visibility. Disable/re-enable voice and verify current session stops within the 30-second check window; duration is independently enforced.
3. Repeat with a second tenant and distinctive knowledge. Try expired/used links, cross-tenant access, quota/concurrency denial and short duration. Check key never appears in network replies, logs or bundle.
4. Keep phone gates disabled. Follow the **exact first real-call procedure** and A–S acceptance in [Vobiz sign-off](./live-vobiz-signoff.md) only after separate approval. Signature-emission setup remains unresolved; do not guess fields or turn on readiness to discover it. Real KYC, paid provisioning/calls/releases need explicit action.
5. Record build/configuration revision, observed timings, restricted references and outcome; strip tokens/identity/phone numbers from shareable records. Customer launch remains conditional on carrier/KYC/number evidence.

Emergency stop: disable invite issuance in app env; set browser/phone/purchase DB controls false through allowlisted Admin with reason/reference. Set both phone/purchase env switches and both provider attestations 0 as defence in depth. Rolling checks stop active streams within 30 seconds; duration guard remains. For immediate stop, close the bridge process/current sockets; carrier callers must hang up and provider termination needs approval. Removing an AI key alone does not end an established Gemini session.

Suspend affected tenants, preserve encrypted credentials, usage and immutable ledger, and pause reconciliation only when investigating a billing defect. Read owning-number/CDR state before approving recovery; never repeat ambiguous purchases/releases. Reverting application deployment does not reverse provider spending. Additive migrations can remain; do not restore/delete billing history or regenerate the master encryption key. Preserve BYOK records when disabling managed alpha. Public signup must remain invite-gated even during rollback; do not expose an old public-signup deployment.
