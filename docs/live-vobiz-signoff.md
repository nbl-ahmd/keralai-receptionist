## Rollback and recovery

1. Set app AND bridge readiness flags 0, redeploy/restart those services and verify new answers produce busy XML and phone handshakes are denied. It blocks NEW traffic; caller/operator must end existing calls explicitly. Keep browser/legacy Exotel available.
2. Suspend affected numbers/tenants with an allowlisted operator; pause reconciliation if investigating a billing/state defect. Pausing KeralAI does not stop provider rental or release an owned DID. Do not rebind parent/default production routing without approval.
3. Preserve public database rows, encrypted credentials, immutable ledger and signed-event digests. Resolve final CDRs/holds read-only first; authorize reconciliation separately. Never delete history or rotate encryption key as a rollback.
4. Application rollback uses the prior deployment; migrations 009/010 are additive and remain. Financial/state recovery should normally be forward/audited. A full database restore requires a maintenance freeze and reconciliation of provider purchases/calls after the restore point; restoring DB alone does not reverse provider spending.
5. Release is a separately approved PAID provider mutation, standard pending 24h. Keep releasing state and do not repeat DELETE.
